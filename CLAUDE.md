This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Rails app for running Secret Santa groups: users sign up, create or join groups via a join code, add gift ideas, and the group owner assigns secret santa partners. Deployed to Fly.io (`fly.toml`, `Dockerfile`) automatically on push to `main` once lint and tests pass.

The stack is deliberately self-contained: SQLite only. Dev/test use a single database at `db/<env>/data.sqlite3`. Production uses four SQLite databases on the Fly volume at `/data` (primary plus Solid Cache, Solid Queue and Solid Cable, each with its own `db/*_schema.rb`); Solid Queue runs inside Puma via `SOLID_QUEUE_IN_PUMA`. Frontend uses importmap + Stimulus + Turbo for JS (no Node build step), and `tailwindcss-rails` for CSS. Ruby version is pinned in `.tool-versions` (asdf).

## Commands

```bash
bin/setup                                  # install gems, prepare DB
bin/dev                                    # Rails server (port 3000) + Tailwind watcher (Procfile.dev)
bin/rspec                                  # all tests
bin/rspec spec/models/join_group_spec.rb   # one file
bin/rspec spec/models/join_group_spec.rb:12 # one example
bundle exec standardrb                     # Ruby lint (use --fix to autocorrect)
npx prettier --check .                     # JS/other lint (requires Node)
```

CI (`.github/workflows/test.yml`) runs `RAILS_ENV=test bin/rails assets:precompile` before specs — feature specs need compiled Tailwind assets, so run that (or have `bin/dev` running) if styles/assets are missing in tests.

Lefthook pre-commit runs prettier and standardrb `--fix` on staged files. It doesn't run the specs, so run `bin/rspec` before committing.

## Architecture

- **Authentication** (`app/controllers/concerns/authentication.rb`): hand-rolled and passwordless. Sign in and sign up both email a magic link (`SessionMailer#sign_in_link`, sent via `send_sign_in_link`), and the response is the same "check your email" page whether or not an account exists. The link is `GET /session/magic_link?token=…` (`MagicLinksController`); the token is `User.generates_token_for :sign_in`, valid for 15 minutes and single-use because it embeds `last_signed_in_at`, which `User#record_sign_in` bumps. GET only shows a "Continue as …" confirmation; the button POSTs the token so email scanners/prefetchers can't burn it, and that POST sets the encrypted `user_id` cookie. `session[:join_code]` is baked into the link as `join_code=…` at send time (the link may open in another browser), and a join code redirects to the join page after sign-in. Controllers opt in to protection with `before_action :require_logged_in`.
- **`Current`** (`app/models/current.rb`): `CurrentAttributes` holding `user` and `group`. Setting `Current.user` also sets `Current.group` to the user's last group — the app has an implicit "current group" concept that the dashboard and `User#ideas_in_current_group` depend on.
- **Domain models**: `User` ↔ `Group` through `UserGroup` (membership); `Group#owner` is a `User`; `Pair` (user → other, scoped to a group) is the secret santa assignment, generated by `Group#assign_partners` (needs >2 members; reshuffles until no self-pairings); `Idea` belongs to a user and group.
- **Action/form objects in `app/models/`**: multi-step operations live in plain `ActiveModel` classes rather than controllers — e.g. `JoinGroup` (`save`) and `RemoveGroupMembership` (`perform`, collects flash `messages`, clears pairs when membership changes). Follow this pattern for new non-trivial operations.
- **Controllers** pass data to views via `render locals: {...}` rather than instance variables. Flash types `success` and `error` are added alongside `notice`/`alert` and rendered by `app/views/shared/_flashes.html.erb`.
- **Rate limiting**: `rate_limit` on `SessionsController#create` (per IP and per email) and `UsersController#create` (per IP); counters live in `Rails.cache`, so they are inert in dev's `:null_store` (test uses `:memory_store`, cleared before each example).
- **Manage Group** (`groups#edit`, owner-only): name/rules form plus "Get ready for next year" resets — `DELETE /groups/:group_id/pairings` and `/ideas` (`GroupPairingsController`, `GroupIdeasController`) call `Group#remove_pairings` / `#remove_ideas`.
- **Join flow** (`JoinController`): `/join/:join_code` links work for logged-out users by stashing the code in the session and picking it back up after sign-in/sign-up.
- **Icons**: `IconComponent` (`app/components/`, ViewComponent) inlines Heroicons (24px outline) from `app/assets/images/icons/<name>.svg`; use the `icon(:name, size:, class:, aria:)` helper. Icons are `aria-hidden` unless given an `aria-label`, so the surrounding button/link supplies the accessible name. Sources hold only drawing attributes (`spec/assets/icons_spec.rb` enforces it), so strip `aria-hidden`/`data-slot` when adding a Heroicon. No emoji in the UI.
- **Group rules** are Markdown, rendered by the `markdown` helper (`ApplicationHelper`: Commonmarker, raw HTML off, output sanitised) inside a Tailwind Typography `prose` container.
- **Email changes** (`UpdateAccount`, `EmailConfirmationsController`): the account form saves the name directly, but a new email is held in `users.unconfirmed_email` and a link (`generates_token_for :email_change`, 1 hour, tied to the pending address) is mailed to it by `UserMailer`. The GET landing auto-submits a POST that calls `User#confirm_email_change`; works signed out. Only email-changing submits count toward the `update` rate limit.
- **Forms**: `FormBuilders::TailwindFormBuilder` (`app/lib/form_builders/`) is set as the global default form builder in `ApplicationHelper` and applies Tailwind classes to fields.
- **Mail**: Action Mailer sends through Resend (`resend` gem, `:resend` delivery method). Env vars: `RESEND_API_KEY`, `MAILER_FROM` (must be on a Resend-verified domain in production), `APP_HOST` (link host, defaults to the Fly hostname). In dev without `RESEND_API_KEY`, mail uses the `:test` method. Either way, dev mail is printed decoded to the log by the `DevelopmentMailLogger` observer (`lib/development_mail_logger.rb`), so follow the sign-in link from the `bin/dev` output. Production sends via `deliver_later` on Solid Queue; the test env uses the `:inline` queue adapter so mail lands in `ActionMailer::Base.deliveries`. Mailer previews live in `spec/mailers/previews`.

## Testing

- RSpec with FactoryBot (`spec/factories`), Capybara + Cuprite (headless Chrome) for feature specs; Cuprite is the default driver for all feature specs.
- Fast sign-in for tests: `Middleware::Test::Authentication` (`lib/middleware/test/authentication.rb`, mounted only in the test env) exposes a path that sets the auth cookie. Use `authenticate(user)` in feature and request specs (`spec/support/helpers/authentication_helper.rb`); `sign_in(user)` (feature specs) drives the real flow instead: request a link, read the URL from the last delivered email (`last_magic_link_url`), visit it (the page signs in by itself via JS). `follow_magic_link` does the last two steps.
- Request specs live under `spec/requests/` organised by resource path; model specs cover the action objects.
